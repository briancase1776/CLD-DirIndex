Directory Index Format
======================

PURPOSE
  Instructs Claude how to write and maintain a directory index file.
  Lives in spec/dir-index-format.txt -- do not copy into index files.

FILE
  Named index.cld, placed in the directory it describes.

FORMAT
  Line 1 : INDEX <path/>
  Lines 2+: <T> <name>    <description>

TYPE LETTERS
  The letters follow find(1)'s -type codes, uppercased, so there is
  nothing new to learn:

    F  regular file
    D  directory                 (trailing slash on the name)
    L  symbolic link
    P  FIFO (named pipe)
    S  socket
    B  block device
    C  character device

  THE LETTER DESCRIBES THE DIRECTORY ENTRY, NOT WHAT IT POINTS AT. A
  symlink is L even when it resolves to a regular file -- the thing in
  this directory is the link. This matches find -type l and ls -l, and
  it is the only rule that stays true when the target moves or dies.

  In practice a git-tracked repo sees F, D and L and nothing else: git
  cannot store a fifo, socket, or device node at all (git add accepts
  them silently and tracks nothing). The remaining letters exist so the
  format can describe a real directory truthfully -- an image being
  staged, a /dev listing, a distro tree -- not because a repo will
  produce them.

RULES
  - One entry per file/subdir; skip generated files and build artifacts.
  - Where a file carries a brief marker at the top (conventionally
    @brief), use it as the primary source when writing the description.
    If it is missing, append [NO BRIEF] to the entry and ask. [NO BRIEF]
    entries are greppable -- do not remove until the brief is added.
    Nothing mechanical checks this: a missing brief is a defect in the
    source file, not in the index.
  - Write the shortest accurate description possible. If it still
    needs more than one clause, leave it -- that flags the file for
    splitting. Don't force it short and don't pad to fill it out.
  - No semicolons -- a description that needs one flags a file to audit
    for splitting.
  - No quotes. No trailing period.
  - Align all descriptions to the same column within the file.
  - Omit files whose purpose is obvious from the directory name alone.
  - Keep this index current: when you add, remove, rename, or edit a
    file in this directory, update the index in the same commit.

NAMES WITH SPACES
  An entry name may contain single spaces ("Tree Palette.html"). The
  description is separated from the name by TWO OR MORE spaces -- that
  gap, not a column rule, is what the checker splits on.

ENFORCEMENT
  scripts/index-audit/check.sh reads this format mechanically. It blocks
  a commit on ORPHAN (an entry names a missing target) and on NOENTRY
  (an indexable file has no entry), and warns on BADHDR (line 1 is not
  "INDEX <path/>") and WRONGTYPE (the entry's letter disagrees with what
  the thing actually is). The skip list in cld.conf is the SINGLE place
  a "do not index this" decision is recorded.

  A dangling symlink is NOT an orphan. The link is present in the
  directory and the entry describing it is telling the truth; where it
  points is the target's problem, not the index's.

EXAMPLE
  INDEX lib/
  F cache.js           In-memory result cache over SQLite; mutex-guarded writes
  F errors.js          Error and perf logging; see notes/errors.md
  F interceptor.js     Intercepts outbound XHR; 9 endpoint handlers
  D utils/             Low-level shared helpers
  L current.json       Symlink to the active config in versions/
