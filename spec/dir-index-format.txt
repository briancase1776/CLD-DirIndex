Directory Index Format
======================

PURPOSE
  Instructs Claude how to write and maintain a directory index file.
  Lives in spec/dir-index-format.txt -- do not copy into index files.
  The other species, the per-file symbol index, is
  spec/file-index-format.txt.

FILE
  Named index.cld, placed in the directory it describes. Only a file
  named exactly index.cld is a directory index, and an index.cld is
  never read as a symbol index, whatever its line 1 says.

FORMAT
  Line 1 : INDEX <path/>
  Lines 2+: <T> <name>  <description>

  <path/> is the directory's path from the repo root, with a trailing
  slash: INDEX lib/utils/. The root index is INDEX ./ (INDEX . is
  accepted too). The path is compared after normalising, so lib,
  ./lib/ and lib/ all name lib/.

TYPE LETTERS
  The letters follow find(1)'s -type codes, uppercased, so there is
  nothing new to learn:

    F  regular file
    D  directory                 (trailing slash on the name)
    L  symbolic link
    P  FIFO (named pipe)
    S  socket
    B  block device
    C  character device

  THE LETTER DESCRIBES THE DIRECTORY ENTRY, NOT WHAT IT POINTS AT. A
  symlink is L even when it resolves to a regular file -- the thing in
  this directory is the link. This matches find -type l and ls -l, and
  it is the only rule that stays true when the target moves or dies.

  In practice a git-tracked repo sees F, D and L and nothing else: git
  cannot store a fifo, socket, or device node at all (git add accepts
  them silently and tracks nothing). The remaining letters exist so the
  format can describe a real directory truthfully -- an image being
  staged, a /dev listing, a distro tree -- not because a repo will
  produce them.

WHAT GETS AN ENTRY
  - Every indexable file in the directory, and every subdirectory. An
    indexable file is one whose extension is in CLD_INDEXABLE_EXTS
    (cld.conf; default js md txt html css json sh). A .cld file is never
    indexable: an index never lists itself or a symbol index.
  - Other files (images, binaries, extensionless files such as LICENSE)
    may be listed or left out; nothing requires them.
  - A file or tree that should carry no entry at all -- vendored,
    generated, build output -- is named in CLD_SKIP_RE (cld.conf). That
    is the SINGLE place a "do not index this" decision is recorded;
    there is no "obvious enough to omit" exception, because an
    unskipped indexable file with no entry blocks the commit (NOENTRY).

RULES
  - One entry per thing. One physical line per entry.
  - Where a file carries a brief at the top (conventionally @brief), use
    it as the primary source for the description. When it has none,
    write the description from the file and move on. No hand-maintained
    marker, and no checker finding: a missing brief is a defect in the
    source file, not in the index.
  - Write the shortest accurate description possible. If it still needs
    more than one clause (a semicolon), leave it that way -- that flags
    the file for a look at splitting. Don't force it short and don't pad
    it out.
  - No quotes. No trailing period.
  - Separate the name from the description by TWO OR MORE spaces (see
    NAMES WITH SPACES). Align the descriptions to one column when it is
    free; NEVER re-pad an existing file to admit one longer name -- an
    overhang is not a violation.
  - Keep this index current: when you add, remove, or rename a file or
    subdirectory, update the index in the same commit. When an edit
    changes what a file does, update its description.

NAMES WITH SPACES
  An entry name may contain single spaces ("Tree Palette.html"). The
  description is separated from the name by two or more spaces. The
  checker does not rely on that gap or on any column: it resolves a
  name by trying the entry's word prefixes, longest first, against what
  is really in the directory, so a ragged or overhanging entry is still
  read correctly.

ENFORCEMENT
  scripts/index-audit/check.sh reads this format mechanically.

  Blocks a commit:
    ORPHAN     an entry names something that is not in the directory
               (including a path the commit deletes or renames away)
    NOENTRY    an indexable, unskipped file has no entry
  Warns only:
    BADHDR     line 1 is not "INDEX <path/>" (the body is still checked;
               a line 1 that is not a header is read as an entry)
    WRONGPATH  line 1 names a directory other than the one the index
               sits in
    WRONGTYPE  the entry's letter disagrees with what the thing is
    CRLF       the file has CR-LF line endings (it is read with the CRs
               stripped, so the other findings still hold)
  Warns only, and only in a sweep (no argument, or a directory
  argument), never at commit time:
    NOINDEX    a directory holding indexable files has no index.cld
    NODENTRY   a subdirectory holding tracked, unskipped files has no
               entry in its parent's index.cld

  A dangling symlink is NOT an orphan. The link is present in the
  directory and the entry describing it is telling the truth; where it
  points is the target's problem, not the index's.

  An index.cld that is another format altogether, one that only shares
  the name, is exempted with CLD_NOT_DIR_INDEX_RE (cld.conf); its
  directory then counts as having no index.

EXAMPLE
  INDEX lib/
  F cache.js           In-memory result cache over SQLite; mutex-guarded writes
  F errors.js          Error and perf logging; see notes/errors.md
  F interceptor.js     Intercepts outbound XHR; 9 endpoint handlers
  D utils/             Low-level shared helpers
  L current.json       Symlink to the active config in versions/
